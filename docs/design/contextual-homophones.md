# 同音词的上下文重排

个人 fork 的已授权需求：在严格拼音范围内，利用已输入上文提高同音词首选准确率。
需求入口在 [个人定制](../plan/personal-macos-customization.md)，术语在 [CONTEXT.md](../../CONTEXT.md)，调研依据在 [调研记录](../notes/context-ranking-research-20260927.md)。

## 行为契约

候选仍由现有词库和拼音规则生成。本地模型只提升已有候选，不生成词、不放宽完整拼音；`liuchu` 不因模型恢复“流传／流畅”。
复用已有“本地整句模型”开关和异步打分线程，不增加服务、下载或云端调用。

先按原有规则显示候选，macOS 停键 80 ms 后发起本地评分；模型尚未加载、评分缺项或失败时继续原有结果。
用户已翻页或移动高亮后不更新当前候选页，沿用上游保护。80 ms 是防抖时间，不是结果呈现的总耗时保证。

只比较首选所属读音组中，覆盖全部输入、非简拼、末音节完整、无纠错／模糊音代价的前 12 个词。
其他切分、前缀词、辅码筛选和形码混输保留原有排序。固定位置短语在重排后插入，位置不变。

评分为 `0.5 × log P(词 | 上文) + 个人偏好加分`，偏好复用 `0.5 × ln(1 + min(次数, 20))`。次数取个人词频与同输入选词次数的较大值；两张表通常来自同一次选择，不重复加分。
个人数据仍提供偏好，但大量历史次数不再绝对压过明确语境。最佳加权分比第二名至少高 1 nat 才提升一个词，其他词保持相对顺序。
没有上文、优势不足、零模型权重、私密输入都不做此词级提升；不改变既有整句路径评分。
阈值是当前小模型的保守工程取值，尚无用户真实语料证明其最优，不能由四个合成例子推算整体准确率。

## 上文与失败处理

优先使用应用提供的光标前文，最多 64 字。明确的空上文不改用历史；应用无法提供时使用当前连续输入的本地历史。
断开输入链时清空这份历史、应用前文和神经缓存，避免失焦或移动光标后的旧内容影响新位置。
上下文变化立即作废缓存，异步结果按前文校验；每次查询重新收集当前所需文本，避免为已删除的拼音发起旧请求。
评分长度错误或含非有限值时整批舍弃。诊断仅增加上文来源、字数和请求数量，不增加正文日志。

已有本地输入日志的开关和记录范围不因本功能改变。此改动不迁移微信上下文映射，也不改写个人词频文件。

## 验证和回退

固定词库测试覆盖强／弱语境、历史回退、严格候选集合、固定短语、歧义切分、异步回填、旧请求、失焦和无效分数；保留修复前失败证据。
随包真实模型用公开合成语境做 CLI 对照，验证目标是“上海／伤害”“权利／权力”两组，不能代表任意同音词。
全工作区测试、格式和 Clippy 通过后才打包安装；系统输入会话仍需实体键盘验收。

关闭已有本地模型开关即可恢复词频排序；保留安装前应用与用户数据备份，可回退整个版本。Git 将上游合并与功能实现分为独立提交。
