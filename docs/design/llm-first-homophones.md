# 大模型主导同音词首选

状态：本机 4B 已实测，速度接近目标但发生明确误提升，不采用为默认首选；用户要求停止 9B 下载，已停止。当前转向决策模型项目调研，尚未接入输入法。现有已交付行为仍见 [小模型上下文重排](contextual-homophones.md)。

## 已确认的目标

- MLX 是 Apple Silicon 本机推理的首选。低占用、节能的边界内，以语境选词能力为主要目标。
- 准确率优先于速度与模型体积。首先检查净纠正与误提升，不能仅因速度快或平均准确率略升就接管首选。
- 大模型是同音词首选的主要判断者，个人历史习惯参与权衡。现有小模型不再决定是否有资格调用大模型。
- 本地是否合适由本机首选决策延迟判断；达不到体验要求时可与用户商定云端模型，不自动开通或消耗付费 API。
- 严格全拼约束、候选放大、英文标点与个人学习数据保留。输入法安装后的启用及实体键盘验收由用户完成。

## 首选规则

1. 词库和严格拼音先限定合法候选。大模型获得上文、拼音及合法候选，返回相对排序；这一途径不让模型自由改写拼音或续写文本。
2. 有上文且存在多个完整同音候选时，默认让大模型参与，不要求原小模型先判为困难。无上文时以个人偏好和词频为主。
3. 语境优势明确时以大模型为主；优势接近时个人习惯决定首选。原始累计次数不能线性相加到模型分数上，避免迁移的高频记录压过新语境。
4. 第一版拟对个人偏好施加有上限的对数修正，使最强与最弱历史偏好的相对影响不超过 2 倍。该参数是待验收的初始工程值，不是“模型正确概率”；不采用任意的固定七三权重。4B 实测中，这一修正仍救不回部分“食盐”错误，不能把该系数当成可靠性的保证。
5. 当前输入中用户的明确选择优先。用户已经移动高亮、翻页或按下确认，模型结果不得改变这次选择；上屏文字不追溯替换。自动首选与用户主动纠正须区别对待，避免模型的选择自我强化。

## 响应与上下文

本地候选立即可用；大模型结果对应同一输入版本及上文时，允许在用户尚未操作候选前提升一次首选。结果过期、超时或失败时维持即时候选，不能阻塞空格上屏。

沿用已有上文边界：应用光标前文优先，无法读取时用当前连续输入历史；明确空前文不代入别处历史，焦点或输入链变化立即作废。拟扩展到最近 128–256 字，保留当前句，避免把无关旧段落当成主要依据。

在上屏后预处理已确定的上文，在组句时复用此前缀；当前字母变化只更新请求后缀。缓存须验证精确 token 前缀，不复用旧答案。服务只保留最新输入请求，取消旧计算，单并发，关闭思考及长文本生成。

## 本机与云端取舍

Qwen3.5-4B MLX 4-bit 已测：直接输出候选词 P50 244 ms、P95 247 ms；字母标签分布的固定指令缓存路径 P50 321 ms、P95 329 ms。两种路径均受候选顺序影响，出现清晰语境下的误提升，故不接管首选。完整结果见 [测速记录](../notes/mlx-context-benchmark-20261014.md)。

热态中位数 300 ms、P95 600 ms 是体验目标，不是凌驾准确性的硬门槛。用户接受比较云端，但本轮未调用付费 API。按 [决策模型筛选](../notes/decision-models-20261014.md)，云端优先验证 Jev 的中文选词能力，本地优先候选为 Laya-multilingual + MLX；这些项目尚未在本机跑分，不使用厂商速度替代本机或完整网络请求时延。

云端采用同一候选选择契约，保持严格拼音和个人权重在 Core 内；供应商、模型、费用和允许发送的上文范围需在实际启用前确定。

## 验证与交付边界

本轮 [测量工具](../../tools/context-bench/README.md) 使用公开样例、真实候选集合及位置变化，分别测试无前缀缓存、固定指令缓存和当前上文缓存。记录选词对照、峰值内存和分阶段时延；没有测量的电量数字不参与结论。

接入阶段再用真实异步逻辑覆盖拼音边界、模型与高频偏好冲突、弱语境、用户主动选择、迟到结果、无上文、失焦、服务超时及断连。新行为需先失败再修复，并通过既有回归后安装。

评测同时记录原首选、模型首选、可接受答案集合、候选置换结果、纠正数、误提升数和强语境错误。`制定／制订`这类可接受变体与`炒菜→实验`分开计。私有输入日志与学习数据只用于本机诊断，不写入公开评测或提交。
