# 语境挑战者与个人选词学习

状态：2026-10-14 按用户认可的方案与 grill-with-docs 问答收敛。本文替代此前“模型概率乘以最多 2 倍历史偏好”的草案；尚未实施新模型与新学习规则。现有已交付行为见 [上下文重排](contextual-homophones.md)。

## 目标与已确认决定

降低同音词选择与纠正成本，准确率优先，默认融入普通输入。MLX 是本地首选；本地不合格时可商议云端。保留严格拼音、候选放大、英文标点与已有个人数据；9B 下载和本机测试保持停止。

用户确认：

- 合法性由规则保证，语境模型只在符合当前拼音的候选中选择。
- 采用挑战者制：通常保留原首选，语境优势足够才提升其他候选。
- 个人偏好只在模型近似平局时裁决，不与明确语境争夺首选。
- 高频原首选提高被挑战的门槛，明确语境仍可突破。例如“炒菜加入少量 shiyan”应允许食盐超过个人常用的实验。
- 词典外名字、术语、临时组合仍可输入；严格限制的是获得学习加分，不以未收录为由全部过滤。
- 验收目标：原首选正确的独立测试样例中，误改率 ≤0.5%；净纠正收益为正，明确语境的已知典型错误全部通过。该目标不等于真实使用中永不超出该比例。

## 两层边界

**合法性层**确定读音、切分与输入覆盖范围。普通分段候选继续用于逐段输入；参与首选挑战的候选必须覆盖同一段完整输入，不把短前缀、自动补全与完整答案混比。完整覆盖不等于汉字等长，保留 `xian → 现 / 西安`。

“词典词或合法组合”不是一张词典能完整判定的集合。`的一个` 可出现在“我买的一个杯子”中；它的问题是 `diyige` 下借用普通“的”的文本统计挤掉“第一个”。修复应约束读音证据、个人统计与整句插入关系，不删除字符串或所有 `的/di`，不清空学习库。现有消融也表明，去掉用户词表并不能修复这个样例。见 [诊断与回归范围](../notes/ordinal-candidate-20261014.md)。

**语境层**接收上文与通过规则的候选，判断哪一个自然接续。模型不能创造候选、改拼音或修改已上屏文本。专用决策模型、生成模型的受限选项打分都按同一效果标准衡量，不按名称选型。

## 挑战与平局裁决

1. 先显示规则与基础排序给出的原首选，保证普通打字和空格确认即时可用。
2. 有有效上文及多个完整同音候选时，让唯一的主语境模型判断；不让现有弱模型决定是否值得调用。
3. 模型推荐不同候选时，同时检查对原首选的优势和对其他竞争者的优势。高频完整词采用更高门槛，但没有不可突破的高频否决权。原始排序分的量纲不能直接与模型概率相加。
4. 模型认为多个候选接近时，只在这个近似平局集合中使用已生效的语境偏好。没有可靠偏好，或仍不能判定，就保留原序；个人习惯不得把明显低概率词抬为第一。包含平局裁决在内的最终策略一起接受误改率评测。
5. 阈值在开发集上选择，随后冻结；模型版本、提示词、候选范围或量化版本变化均须重测。原始置信度高并不直接赋予改首选的权利。
6. 每次输入至多自动提升一次；用户移动高亮、翻页或确认后冻结。过期、失焦、超时、无效结果保持原序，不等待模型，不追溯改字。

沿用光标前文优先、连续输入记录兜底的现有边界；明确空前文不使用另一输入框历史。具体请求防抖和等待上限按本机端到端测量确定，P50 300 ms / P95 600 ms 仍是体验目标，不是质量豁免。

## 学习规则

个人偏好以“输入拼音 + 上文片段/特征 + 被选候选”为作用范围，新证据不继续累加成无限制的裸词频。

| 行为 | 学习用途 |
|---|---|
| 主动选择后面的候选、明确纠正模型提升 | 强正信号；纠正模型时对被拒绝项记当前语境负信号 |
| 同一输入位置撤销后，用相同拼音改选其他词 | 能可靠关联原上屏事件时计纠正；关联不明则不推断意图 |
| 直接空格接受首选 | 首版不增加持久偏好；避免模型给自己制造训练标签 |
| 普通退格、光标移动、改写句子 | 不自动认作负反馈 |

推荐首版参数：新条目需 3 次独立组句中的主动选择才获得加分，证据按 30 天半衰期衰减；负证据同样局限于该拼音与语境。这是待回放调参的起点，不是已测出的最佳值。高频 n-gram 必须来自合格的主动信号，不能靠重复接受错误首选获得成词资格。

保留迁移前与变更前数据快照。旧裸词频不能反推为带语境的强信号；修复旧统计参与排序的方式，新增学习采用上述规则。历史数据清理若确有必要，须先生成可审查清单与可恢复备份，不在本轮删除。

## 模型选择与验证顺序

详见 [中文决策模型筛选](../notes/chinese-decision-models-20261014.md)。本轮只确定评测对象，没有下载新权重或调用云端。

1. **先修规则与学习缺陷。** 用可公开合成数据复现 `diyige`，修复后验证 `deyige`、多音字、完整词、临时组合及严格拼音回归。这部分不依赖云端模型。
2. **固定同一批选词样例，比较能力。** 本地首先考察 Decision-2.0-Sol-2B 的 MLX 转换；云端比较 Microsoft-Decision-1 与 TypeSafe Jev。云端使用公开样例；账户、费用与授权明确后才调用。它们是独立对照，不组成逐级请求的线上链条。
3. **质量过线才比较成本。** 按误改率、净纠正和明确语境表现筛选；合格且差距未证实时优先本地。若本地质量不达标，优先选合格的云端方案，不因低内存强行采用弱模型。云端质量好但结果总是赶不上确认，也不能称为有效改进。
4. **只接入胜出的一条主路径。** 先旁路记录决策，不改变实际候选；回放通过再启用挑战者策略。失败随时退回基础排序，不搭建多模型串行补救。

Microsoft-Decision-1 是云端候选，其官方基座为后训练的 Qwen3.5-9B；本方案不下载或本机测试该权重。首次云端测评范围与费用待执行前确定。新模型安装后的输入源启用和实体键盘验收由用户完成。

## 验证、失败处理与交付

开发集用于调整提示和门槛；独立测试集按语境/词族隔离，不能把同一例的候选置换分到两边。先建立至少 200 条开发样例及 1,000 条独立测试样例，涵盖强弱语境、常用虚词、序数词、多音字、名字术语、历史冲突与候选缺失。候选顺序置换作为同例的稳定性检查，不能扩充成独立样本。

误改率分母是原首选正确的样例数；同时报告实际替换中错误的比例、纠正数、净收益、干预覆盖率及置信区间。没有足够分母时不声称达到低误改率；例如零错误的 600 条原首选正确样例，单侧 95% 二项上界仍约 0.5%。多义或近义表达使用可接受答案集合，避免把合理变体算错；不可判定样例另列。

评估分开检查候选召回和选词：目标根本不在池中时，不把它当成模型能解决的问题。高频保护、平局学习、新词门槛与衰减必须用完整策略回放验证，不能只测模型裸分数。

真实异步测试覆盖输入变化、选词冻结、服务失败、迟到结果；学习测试覆盖重复接受不强化、主动纠正、无关退格、跨输入框污染和衰减。行为改动必须先失败后通过。现有 16 个语境仅是回归种子，不足以证明 ≤0.5%。

资源测量使用本机 M1 Pro 的单次真实输入请求，记录冷启动、P50/P95、内存、持续输入与空闲行为；不把服务器 GPU 或社区 M4 数字写成本机结果。没有能耗数据时，不给出省电百分比。
