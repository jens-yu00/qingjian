使用方式见 [偏好设置](../user/settings/preferences.md)，测试与安装证据只维护在 [验证记录](../notes/personal-macos-validation.md)。

## 稳定的体验约束

- 候选缩放为 100%–250%，每档 25%；应用内行内拼音字号由应用决定。
- 英文标点开关不切换中英文模式。组句中按快捷键不上屏、不清空输入、不移动候选高亮；长按只切一次。
- 标点按键、翻页、英文直输、用户主动确认候选的行为沿用原有约定。
- “严格全拼匹配”开启时，完整音节按原样匹配；若存在全部音节完整的切法，保留这些切法并排除夹杂简拼的另解。
- `liuchu` 保留留出、流出、六畜以及可逐段确认的前缀词；排除流传、留长、流畅和自动续出的流处理。
- `liuchuan` 可出流传；`liuch`、`lc` 等未完整输入继续补全；`xian` 的 xian / xi an 两种完整切法都保留。
- 严格匹配禁用全拼自动拼写纠错与模糊音扩展，不删除学习记录。同音词排序、个人学习、本地整句组合保留。
- 严格规则同时约束云端词的拼音；用户主动使用的云端整句补全保持原约定。本机云联想目前关闭。
- 双拼、注音和英文模式不受这个全拼设置影响。

## 实现与失败处理

- Core 拥有匹配策略；macOS 原生设置和 CLI 只读取 `general.strict_pinyin` 并传给 Engine。
- 旧配置缺项为 false，保持原有体验；本机显式启用 true。一个设置覆盖此次明确的完整音节补长、简拼另解、自动纠错三类问题。
- 切换时作废纠错、词图缓存与未完成的云请求，避免旧策略结果继续上屏。保留原始模糊音配置，关闭严格模式可恢复。
- 配置解析失败沿用上一份有效配置；构建或测试失败先修复，不把失败产物交付为可用版本。
- 应用安装前备份现有应用和配置；不自动注销会话、不修改系统安全设置。

## 验证与交付

1. 用固定词库回归测试证明修复前失败、修复后通过；覆盖完整匹配、简拼补全、拼音歧义、逐段确认、纠错缓存、模糊音和云端词。
2. 用产品词库和本地模型检查 liuchu、liuchuan、liuch、meiganxi 的候选；区分确定性 Core 结果与个人学习后的具体排序。
3. 运行 workspace 测试、fmt、Clippy；打包、校验签名、备份并更新本机应用。
4. 记录构建版本、实际配置及未完成的系统验收；不把 CLI 或窗口预览当作真实输入会话测试。
