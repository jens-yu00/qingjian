# 上游更新与上下文候选调研（2026-09-27）

## 结论与范围

上游值得合入，建议以已发布的 0.1.4 为基线，在独立集成分支保留个人定制后验证。仅升级不能解决普通同音词不随上文排序的问题：当前随包模型已经能理解部分语境，但词级候选没有消费它的分数；全局选词次数还排在上下文得分之前。

首选方案是复用现有模型，增加受严格拼音约束的短词上下文重排，再评估是否需要更好的中文模型。本轮只抓取上游、进行不改工作区的合并预演、审计源码、运行离线探针及记录方案；没有合并、安装、改配置或改用户学习数据。

## 当前实现实际上做了什么

本机配置核验：`model.enabled=true`、`general.strict_pinyin=true`、候选缩放 150%，云联想关闭。安装版本仍为 `0.1.3-dev` build 67。探针直接加载当前安装包的模型文件，元数据为 `small-155478`、27,950,272 个参数，字级 Transformer；CPU 和 Metal 两种探针均成功运行。这证明文件可用，不代表已经核验当前前台应用的上下文接口。

1. macOS 在一轮组句首键尝试读取光标前文，传给 `Engine::set_rescoring_context`。Core 默认保留最近 64 个字符；应用不返回文本时退回会话上屏历史。切换应用、移动光标等场景还需用实际输入验证可靠性。见 `apps/macos/src/imk/controller/mod.rs::refresh`、`apps/macos/src/imk/client.rs::surrounding_text`。
2. 字级模型计算 `log P(候选 | 前文)`，已有前文 KV 缓存和候选批处理。见 `crates/qingjian-neural/src/scorer.rs`。
3. Core 只给整句转换的前 6 条路径重打分。`plain_sentence` 对词库已有的同文本同读音候选不提升；非纠错的单词路径也不作为整句候选插入。因此模型可以打出正确分数，但普通词仍留在原词级顺序。见 `crates/qingjian-core/src/engine/query/mod.rs` 与 `engine/rescoring/mod.rs`。
4. 词级排序先比较拼音结构，再比较同一输入串的选择次数，最后才比较统计上下文分数。它使用的是上屏词链的统计模型，光标前长文本的神经分没有接到这里。见 `crates/qingjian-core/src/ranking/scored.rs::SortKey`。迁入大量精确选词偏好可能加强该优先级；本轮没有重跑个人数据来量化影响。
5. macOS 默认停键 80 ms 后发重排，已翻页或手动移动高亮时不改候选。快速直接空格确认可能先于模型结果。上游目前保留相同的短词排序边界，`qingjian-neural` 和 Core 重排模块相对旧基线没有新模型逻辑。

## 可复现实验

新增 [context_probe.rs](../../apps/cli/examples/context_probe.rs)，只使用公开合成语境、产品词库、统计语言模型和随包神经模型，不读取个人学习数据，也不调用输入控件或写学习记录。

```sh
cargo run -p qingjian-cli --example context_probe --locked \
  --features qingjian-neural/metal -- \
  "$HOME/Library/Input Methods/Qingjian.app/Contents/Resources/model/model.qjm"
```

| 光标前文 | 拼音 | 模型直接比较结果（对数分，越大越好） | 当前引擎最终顺序 |
|---|---|---|---|
| 我明天坐高铁去 | shanghai | 上海 −4.30；伤害 −14.00 | 上海、伤害、商海 |
| 这种行为会对孩子造成 | shanghai | 上海 −14.87；伤害 −2.85 | 上海、伤害、商海 |
| 每个公民都享有平等的 | quanli | 权利 −1.32；权力 −6.54 | 权力、权利、全力 |
| 他掌握着至高无上的 | quanli | 权利 −4.88；权力 −5.49 | 权力、权利、全力 |

每次完整查询模型实际调用一次；第二、三行直接证明“模型更看好目标词，却未改变词级排序”。第四行也保留，显示小模型自身会判断失误，不能把任何神经意见都无条件置顶。四个样例不是准确率基准。

Metal debug 探针首个打分约 11.35 秒（包括首次内核工作），随后三个不同前文的两候选打分约 24–25 ms；CPU debug 约 467–542 ms。这不是生产 p95，也不包含真实输入控件调用、调度和大候选集合成本。实际实现应后台预热，再测 release、冷/热状态与候选数。

## 可借鉴方案

| 路线 | 原始资料与可借鉴内容 | 对青简的判断 |
|---|---|---|
| 本地短词上下文重排 | [Cassotis IME](https://github.com/shenmin/cassotis-ime#corpus-trained-local-ranking) 的独立短词重排器用光标前文比较精确候选，残差模型仅在优势超过阈值时调整；[基准说明](https://github.com/shenmin/cassotis-ime/blob/master/BENCHMARK.CN.md) 区分短词上下文与长句、准确率与延迟测试 | 最贴近本次目标；参考职责拆分和评测方法。它是 Windows/Delphi 项目，不能直接作为 macOS 插件安装；本轮未实测其效果 |
| 专用神经输入转换 | [azooKey/Zenzai](https://github.com/azooKey/azooKey-Desktop)、[转换引擎](https://github.com/azooKey/AzooKeyKanaKanjiConverter)、[原始论文](https://www.anlp.jp/proceedings/annual_meeting/2025/pdf_dir/P1-19.pdf)：条件神经模型，统计转换器作为草稿加速 | 是神经模型可用于桌面输入法的实际参考；日文假名模型不能直接替换中文拼音模型，需要中文训练数据与约束解码 |
| 更强的统计上下文 | [libime 语言模型实现](https://github.com/fcitx/libime/blob/master/src/libime/core/languagemodel.cpp) 使用 KenLM n-gram | 可低成本改善局部搭配，但不能等同于长上文语义模型，难以单独满足当前目标 |
| 拼音条件化中文 GPT | [ACL 2022 论文](https://arxiv.org/abs/2203.00249) 研究 GPT 与拼音信息结合、同音词区分；完整拼音与简拼表现不同 | 若现有小模型在领域词上不足，可训练/蒸馏更好的中文候选评分器；论文结果不能代替本机评测 |
| 通用大模型逐键生成 | 可以本地或云端运行，但要处理精确拼音约束、延迟和候选抖动 | 首轮不采用。云联想当前关闭；未来若引入，也应先限制为候选 ID 重排或独立补全通路，不能改写严格拼音候选 |

本轮没有下载第三方模型或引入第三方代码。相关模型权重、训练语料和分发许可需在选定具体产物时分别核验。

## 建议实施顺序与验收

1. **先集成稳定上游。** 用独立集成分支解决冲突，完成原有定制回归。模型启动修复值得带入，但不将它误报为普通词上下文问题已解决。
2. **先诊断上文来源。** 记录来源（应用/会话/无）、长度、读取耗时、重排是否触发及放弃原因，不记录正文。分别核验用户主要应用、原生文本框、浏览器和 Electron；切换文本框或移动光标时作废旧请求，读不到就保留可靠退路。
3. **增加词级上下文重排。** 从严格匹配的同等拼音覆盖候选里取一个有界集合（初始可试 8–16 条），复用现有 CharScorer。只改变既有词的顺序，不生成改音词、不自动续出未输入的部分；前缀分段候选和用户固定短语位置保留。
4. **平衡个人习惯与语境。** 将普通全局选词次数由绝对优先改为有上限的得分项，让足够强的上下文能胜出；明确固定位置短语仍优先。弱语境、模型分差小、超时、返回错误或用户已经导航时保持原顺序。不清空迁入词频，先离线评测新排序策略。
5. **再决定模型升级。** 现有模型先建立端到端基线；收集失败类别后，优先同音候选对比训练/蒸馏，避免仅凭模型参数量选择。更大模型应同时满足内存、耗电、尾延迟与真实准确率收益。

建议建立独立验证集，分开统计：有/无前文、单字/短词/整句、普通/专业词、存在强个人偏好、第一键启动与快速确认、上下文不可读/过期。报告 Top-1/Top-3、误提升率和用户改选次数；先覆盖本报告的反向语境对，再加入用户真实失败例，真实文本只保留在本机。

建议初始工程目标（尚未测得、未作为用户承诺）：首屏候选不等待模型；停键后新增重排总等待的 p95 不超过 150 ms；完整拼音不产生近音词；无可用上下文时基线不退化。实际阈值与候选数用本机 release 测量决定。失败时退回原候选与原排序，不自动更换模型或开启云服务。

用户反馈该体验似乎与应用无关，暂时想不起具体例子，以后遇到再提供；不以补交例子作为继续改进的前置条件。尚缺的证据：真实失败例、实际上下文读取成功率、个人词频参与后的影响幅度、改进实现的大样本收益与生产尾延迟。本报告的源码与离线实验已足够确认排序结构存在缺口，但没有声称用户当前应用的具体故障已定位或修复。
