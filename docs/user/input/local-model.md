青简随包带一个几十 MB 的小语言模型，组句时在本机根据上文调整同音词和整句候选。全程离线，不联网、不发送任何内容。

## 怎么生效

敲完一段拼音停一下，模型会在后台判断候选是否符合上文；先显示词库和个人习惯排出的候选，评分完成后再更新。速度取决于设备、候选数量和模型状态。
它会看光标前面的几十个字：同一段拼音在不同上下文里给的句子可能不同。应用不让读上下文时（部分终端、Electron 应用）只看这次会话里输入过的字；Linux 目前只看这次会话里输入过的字。

本定制版也比较完整拼音对应的同音词。例如“这种行为会对孩子造成”之后输入 `shanghai`，可以把“伤害”排到“上海”之前。只有上下文优势明显时才提升候选；判断模糊、没有上文时保留原顺序。个人选词习惯仍然参与排序，自定义短语的固定位置保留。

它不会因为上下文而改掉你输入的拼音。严格全拼匹配继续生效；不完整的拼音、简拼和不同的拼音切分沿用原有排序。应用无法提供前文时，切换输入位置后会清空历史，避免把上一处内容当作当前上文。

## 什么时候不生效

- 已经翻到后面的页或用方向键移过高亮时，模型的结果不再换掉正在看的这页。
- 密码框里不组句；应用声明为私密的输入框里不读上下文。
- 输入法刚启动的几秒钟模型还在加载，这段时间按词库统计出句。

## 关掉

「偏好设置 → 云服务」（Windows：「设置 → 云服务」）关闭「本地整句模型」，或配置文件 `[model]` 里 `enabled = false`（Linux 只有这一种，改完重启青简服务）。关闭后只用词库统计，与云联想互不影响。

## 自己的模型

把 `.qjm` 模型文件放进用户数据目录的 `model/` 下，重启输入法后优先使用（训练仓库直接导出的 `model.safetensors`、`config.json`、`vocab.json` 三个文件放进去也认；两者都有时用 `.qjm`）：

- **macOS**：`~/Library/Application Support/Qingjian/model/`
- **Windows**：`%APPDATA%\Qingjian\model\`
- **Linux**：`~/.local/share/qingjian/model/`

## 本机 Sol 2B 试用（macOS 定制版）

这版可改用 Sol 2B 专用决策模型，根据上文挑选同音词。它不会生成新词或联网。先正常显示候选，停键后约三四百毫秒可能将更符合上文的词提升到第一位；开始翻页或移动高亮后不再调整。

安装好试用模型后，在用户配置文件中设置：

```toml
[model]
enabled = true
sol = true
```

本机运行文件位于 `~/Library/Application Support/Qingjian/sol/`。首次启动约需 8 秒准备，期间仍可正常输入。模型随后驻留内存；关闭“本地整句模型”会释放它。

可试“炒菜时加入少量”后输入 `shiyan`，或“这种行为会对孩子造成”后输入 `shanghai`。没有上文或判断不明显时保留基础候选。模型提升的词暂不积累为全局选词习惯，手动改选其他词仍按原规则学习。

`sol = false` 恢复原来的小模型，`enabled = false` 关闭所有本地模型。模型异常时基础输入继续可用；关闭后重新开启本地模型可重试。此版仍在试用，词典缺失的词不会由模型补出。
